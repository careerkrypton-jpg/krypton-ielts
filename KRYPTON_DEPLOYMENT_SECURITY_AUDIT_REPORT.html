3. The 3 Resolved Issues Explained

Problem 10: Database Row-Level Security

What was it? Default Supabase policy allowed unauthenticated visitors to read all student data and test scores.

Solution: Executed Step 6 RLS lockdown script. Enforced auth.uid() = user_id multi-tenant isolation, protecting student identities, scores, and candidate IDs.

Problem 9: Exposed HTML Reports in Public/

What was it? Vite automatically copies all files in public/ into dist/, exposing internal architecture reports on the public web domain.

Solution: Relocated internal audit files to an isolated reports/ folder. Purged dist/ and verified that production builds only contain web assets.

Problem 2: Production Environment Variables

What was it? .env.local is ignored by Git. Without documentation, production builds on Vercel/Netlify would fail due to missing keys.

Solution: Authored .env.example and .env.production.example with explicit Vercel and Netlify dashboard configuration instructions.

4. Public Deployment Guide for Kathmandu Krypton

A. Deploying to Vercel

  1. Push code to GitHub or import using Vercel CLI.
  2. In Vercel Project Settings ➔ Environment Variables, enter:
    • VITE_SUPABASE_URL: https://xgndntumjdmavihospdw.supabase.co
    • VITE_SUPABASE_ANON_KEY: (Your public anon key)
  3. Deploy! Security headers and SPA routing are automatically applied from vercel.json.

B. Deploying to Netlify

  1. Connect repository to Netlify.
  2. Add VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY in Site configuration ➔ Environment variables.
  3. Deploy! Routing and headers are automatically handled by public/_redirects and public/_headers.

C. Supabase Authentication Setup

Once live on your production domain (e.g. https://krypton-ielts.vercel.app):

  1. Open Supabase Dashboard ➔ Authentication ➔ URL Configuration.
  2. Set Site URL to your production domain.
  3. Add your production domain to the Redirect URLs list.
